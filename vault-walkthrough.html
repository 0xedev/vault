Vault — Walkthrough

NFT-collateralised lending & multi-asset marketplace on Base L2. Single monolithic contract VaultEscrow.sol (743 lines, Solidity ^0.8.28) + Neon Postgres + Next.js 16 App Router + viem + Pusher real-time chat.

1. NFT Lend / Borrow Flow

UI  Borrower Lists NFT

Route: /market → "List your NFT" → ListNFTModal

Step 0 — Scan wallet: Alchemy API scans Base NFTs owned by connected wallet. User selects one from detected collection list (Meridian Genesis, Aperture, BAYC, Azuki, etc.).

Step 1 — Set terms: Loan amount (ETH), APR (%), term (days). Implied LTV shown as bar.

Step 2 — Sign & submit: Signs a message proving intent. Then two on-chain txs fire:

① ERC721.approve(escrowContract, tokenId)

② escrow.listNFT(nftContract, tokenId, amount, apr, term)

NFT transferred into escrow. Listing ID extracted from Listed event. POST /api/listings to persist in DB.

Contract  listNFT

listNFT(address nftContract, uint256 tokenId, uint256 amount, uint256 apr, uint256 term) → uint256 listingId

Validates: amount > 0, term > 0, sender owns the NFT.

Effects: Increments listingCount, stores Listing struct (borrower, nftContract, nftTokenId, principal, apr, term, stage: LISTED).

Transfer: nft.safeTransferFrom(msg.sender, address(this), tokenId) — NFT custody goes to escrow.

Emits Listed(listingId, borrower, nftContract, tokenId, amount, apr, term).

UI  Lender Submits Offer

Route: /market → click LoanCard → /detail?id={listingId}

Lender sees NFT details, borrower terms, existing offers. Two actions:

Match: Accepts existing offer terms (from offer list).

Counter: Opens CounterOfferModal — sets amount, APR, term, expiry. Preview shows total repayment = amount + interest.

On submit: writeSubmitOffer() sends ETH to contract (payable). POST /api/offers records in DB.

Contract  submitOffer

submitOffer(uint256 listingId, uint256 amount, uint256 apr, uint256 term) payable nonReentrant whenNotPaused

Validates: msg.value == amount, listing is at stage LISTED, lender hasn't already offered.

Effects: Records deposit in lenderDeposits[listingId][msg.sender], stores Offer{apr, term}, adds to listingEscrowBalance.

Emits OfferSubmitted(listingId, lender, amount, apr, term).

UI  Borrower Accepts Offer

Borrower opens /detail for their listing, sees pending offers with Accept / Reject buttons.

Accept: Calls writeAcceptOffer() with matching offer params. On chain: ETH released to borrower (minus platform fee), loan moves to ACTIVE. Off chain: PATCH /api/offers with status "accepted".

Live countdown timer starts. Borrower can export repayment calendar (.ics).

Contract  acceptOffer

acceptOffer(uint256 listingId, address lender, uint256 acceptedAmount, uint256 acceptedApr, uint256 acceptedTerm)

Validates: lender deposit ≥ acceptedAmount, APR and term match the recorded offer (OfferMismatch otherwise).

Effects: Excess ETH refunded to lender. Platform fee (acceptedAmount × platformFeeBps / 10000) sent to admin. Net ETH to borrower. fundedAt = block.timestamp. Stage → ACTIVE.

Emits OfferAccepted(listingId, lender, acceptedAmount).

UI  Borrower Repays

Full repay: Click "Repay full amount", sends principal + interest ETH. NFT returned from escrow to borrower.

Partial repay: Click "Partial repayment", sends a fraction. Reduces outstanding balance. If fully paid, auto-closes.

Interest = principal × aprBps × termDays / 3,650,000 (pro-rated).

Contract  repay / repayPartial

repay(uint256 listingId) payable

repayPartial(uint256 listingId) payable

repay: Must cover total due (principal + interest). Transfers remaining balance to lender, returns NFT to borrower. Stage → REPAID.

repayPartial: Partial ETH sent to lender, repaidSoFar incremented. If fully repaid, auto-closes loan.

Emits Repaid(listingId, amount).

UI  Lender Claims Defaulted NFT

After term + 24hr grace period, "Claim collateral" button activates on lender's /detail view. Click calls writeClaimCollateral(). NFT transferred to lender. Loan stage → DEFAULTED.

Contract  claimCollateral

claimCollateral(uint256 listingId)

Validates: block.timestamp ≥ fundedAt + term + GRACE_PERIOD (24 hours).

Stage → DEFAULTED. nft.safeTransferFrom(address(this), lender, nftTokenId).

Emits DefaultClaimed(listingId, lender, nftContract, tokenId).

UI  Dispute & Admin Resolution

Either party clicks "File dispute" on /detail → calls writeDispute(). Loan freezes.

Admin resolves at /admin/disputes: chooses whether NFT goes to lender or borrower, calls writeResolve().

Contract  dispute / resolve

dispute(uint256 listingId) → Stage DISPUTED

resolve(uint256 listingId, bool nftToLender) onlyAdmin

resolve: If nftToLender=true, NFT → lender. Otherwise NFT → borrower. ESCROW balance to appropriate party minus fee.

Emits Disputed(listingId) / Resolved(listingId, outcome, nftToLender).

UI  Seller Lists Asset

Each market has a dedicated page + listing modal:

→ Mini Apps: /miniapps → ListMiniAppModal — name, URL, repo, DAU, MRR, price, deliverable checkboxes (source code, domain, API keys, docs, etc.), DNS TXT verification.

→ X Accounts: /x → ListXModal — handle, followers, price, tweet-pin verification, deliverable options (OAuth, 2FA, email, phone, apps, data archive).

→ Farcaster: /farcaster → ListFidModal — FID number, channel, followers, on-chain FID custody proof, deliverable options (FID transfer, wallet, recovery, signer keys, storage).

→ Clanker: /clanker — token address, chain, sale rights selection (fee rights, admin rights, vaulted tokens, remaining supply).

→ Bundles: /market → ListBundleModal — name, description, cover image, multi-asset form (up to 10 assets of mixed types).

Contract  listDeal / listMiniApp

listDeal(uint256 price, bytes32 metadataHash) → uint256 dealId

listMiniApp(uint256 price, bytes32 metadataHash) → uint256 miniAppId

listDeal: Creates Deal{seller, price, metadataHash, stage: LISTED}. The metadataHash is keccak256(sortedJSON) of off-chain metadata (name, description, deliverables).

listMiniApp: Wrapper that calls listDeal() internally and maps miniAppId → dealId for backward compatibility.

Emits DealListed / MiniAppListed.

UI  Admin Verifies & Buyer Funds

Verify: Admin at /admin/listings reviews and verifies seller ownership. May be auto-approved for some markets.

Fund: Buyer clicks "Buy" on listing page, wallet confirms transaction. ETH locked in escrow. POST /api/escrows creates escrow record. Deal room created at /deals?id={dealId}.

Contract  verifyDeal / fundDeal

verifyDeal(uint256 dealId) onlyAdmin

fundDeal(uint256 dealId) payable nonReentrant

verifyDeal: Stage LISTED → VERIFIED.

fundDeal: msg.value == price, buyer ≠ seller. Sets buyer, stage → FUNDED, deadline = now + 7 days. ETH locked in dealEscrowBalance.

Emits DealFunded(dealId, buyer, amount).

UI  Seller Delivers & Buyer Confirms

Deliver: In deal room (/deals), seller attaches delivery proof (URL + content hash) via POST /api/escrows/{id}/proofs. Then calls writeMarkDelivered(). 3-day buyer confirmation window starts.

Confirm: Buyer verifies asset, clicks "Confirm receipt" → writeConfirmDelivery(). Off-chain validation also runs: for Clanker, verifies token rights transferred. For Farcaster, verifies FID custody on Optimism. Funds released to seller (minus 2.5% platform fee).

Contract  markDelivered / confirmDelivery

markDelivered(uint256 dealId) onlySeller nonReentrant

confirmDelivery(uint256 dealId) onlyBuyer nonReentrant

markDelivered: Stage FUNDED → DELIVERED. deadline = now + 3 days.

confirmDelivery: Deducts platform fee, sends net to seller, remainder (if any) to buyer. Stage DELIVERED → CONFIRMED.

Emits DealDelivered / DealConfirmed(dealId, sellerAmount).

UI  Refund / Dispute

Refund: If seller misses 7-day delivery deadline, buyer's "Claim refund" button activates → writeRefundDeal(). ETH returned to buyer.

Dispute: Either party files dispute → writeDisputeDeal(). Admin resolves at /admin/disputes with split amounts.

Contract  refundDeal / disputeDeal / resolveDeal

refundDeal(uint256 dealId) onlyBuyer

disputeDeal(uint256 dealId) onlyDealParty

resolveDeal(uint256 dealId, uint256 buyerAmount, uint256 sellerAmount) onlyAdmin

refundDeal: Validates block.timestamp > deadline. Returns ETH to buyer.

resolveDeal: Admin splits escrow balance between buyer and seller. Platform fee deducted from seller's portion. Dust sent to admin.

6. Deal Room Flow — End-to-End

1. Buyer deposits fundDeal

Buyer clicks "Buy" on listing. Wallet confirms fundDeal{value: price}(). ETH locked in dealEscrowBalance. 7-day delivery clock starts. Escrow created in DB. Deal room opened.

2. Seller transfers markDelivered

Seller uploads delivery proof (URL + hash) via /api/escrows/{id}/proofs. Clicks "Mark as delivered" → markDelivered(). Stage → DELIVERED. 3-day confirmation window starts.

3. Buyer confirms confirmDelivery

Buyer verifies asset. Clanker: checks fee rights, admin rights, token supply transferred on-chain. Farcaster: checks FID custody on Optimism. Clicks "Confirm receipt" → confirmDelivery(). ETH released to seller minus platform fee.

Timeline & Chat

Deal room shows a 5-step timeline with current position highlighted. Real-time Pusher chat (private-deal-{escrowId}) with AES-256-GCM encrypted messages. Quick replies, image upload, read receipts. Cursor-based pagination.
